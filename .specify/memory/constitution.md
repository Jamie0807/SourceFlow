# SourceFlow 项目宪章

版本：1.0.0
生效日期：2026-09-19
状态：项目级强制原则

## 原则一：规格先于实现

任何新功能、行为变化、数据结构变化和跨端交互必须先有可评审的需求规格、实现计划和任务拆解。代码不是需求的唯一事实来源，spec、plan、tasks 和测试共同构成可追溯交付链。

## 原则二：小步、隔离、可并行

独立特性使用独立 Git Worktree 和任务分支。可以无共享状态并行的任务交给独立智能体；共享领域模型、数据库迁移和核心接口必须先稳定契约或串行执行。禁止把无关重构混进功能任务。

## 原则三：测试驱动和可验证

行为变化先写失败测试，再实现最小行为，再重构。Vitest 覆盖领域与服务端逻辑，React Testing Library 覆盖组件，Playwright 覆盖 Web/H5/API/Electron 关键流程。未验证的完成声明无效。

## 原则四：类型安全和边界清晰

TypeScript 使用 strict mode。前端通过类型化 API 客户端访问服务端；领域模型、平台适配、任务编排、UI 和基础设施职责分离。任何跨端共享都必须有清晰接口和测试。

## 原则五：质量门禁自动化

ESLint、Prettier、Spellcheck、Commitlint、Husky、类型检查、覆盖率、构建、Playwright smoke 和 Docker 校验进入 CI。Pull Request 和 push 质量门禁失败时阻断合并；豁免必须有明确期限和责任人。

## 原则六：安全和隐私默认开启

Secrets 不入库，日志脱敏，服务端校验资源归属，线索和授权信息最小权限访问。数据库迁移可审计、可回滚；删除、导出、断开授权和生产发布具有明确确认和审计记录。

## 原则七：可运维和可回滚

长任务可观察、幂等、可重试、可取消。API、Worker、数据库和 Redis 有健康检查和结构化日志。生产镜像使用不可变版本或 digest，发布有备份、健康检查、回滚和产物校验。

## 原则八：跨端体验一致但不强求代码相同

Web/H5、React Native 和 Electron 共享领域规则、API 契约和业务状态；UI 依据平台交互习惯实现。桌面/Web 服务高效生产，手机/Pad 服务审核、灵感、轻编辑和异常处理。

## 原则九：可访问、可本地化、可解释

交互满足键盘可达、合理对比度、语义化标签和非颜色单一表达。文本考虑中文/英文长度、时区、数字格式和错误文案。AI 建议保留来源、置信度、模型版本和人工修改轨迹。

## 原则十：人工掌控发布和提交

平台不支持自动发布时必须诚实显示辅助发布或导出发布包。智能体不自动执行 Git commit、push、合并、生产部署或不可逆数据操作；用户明确授权提交时统一使用 `pnpm commit`。

## 合规检查

每个功能在 `converge` 阶段必须回答：

- [ ] 是否有 spec、plan、tasks 和需求追踪？
- [ ] 是否有失败测试、回归测试和必要的 Playwright smoke？
- [ ] 是否通过格式、类型、拼写、覆盖率和构建门禁？
- [ ] 是否检查权限、Secrets、日志、数据迁移和回滚？
- [ ] 是否验证 Web/H5、Electron、React Native 受影响端？
- [ ] 是否更新用户文档、开发文档、环境变量和发布清单？
- [ ] 是否没有自动提交 Git 或执行未授权外部变更？
