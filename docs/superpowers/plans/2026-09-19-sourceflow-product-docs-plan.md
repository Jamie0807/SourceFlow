# SourceFlow 产品文档交付计划

> 本计划记录已确认的产品设计以及文档交付过程，不是应用程序的开发实现计划。

**目标：** 为 SourceFlow 生成一套基于市场调研的产品策略，以及覆盖大屏端和小屏端的完整 PRD。SourceFlow 是一个 AI 内容复用与多平台运营工作台。

**文档结构：** 将市场调研、产品策略、功能 PRD、端侧交互规格、付费规则、用户流程和低保真线框拆分为独立的 Markdown 文档，并统一放在一个产品文件夹内。桌面端与 Web 端视为同一套大屏设计；手机与 Pad 视为同一套小屏响应式设计。

**文档形式：** Markdown、Mermaid 流程图、纯文本线框图和公开网页调研链接。

## 全局约束

- 第一目标用户是高频内容创作者和 1—10 人内容团队。
- MVP 核心闭环为：内容源 → AI 复用 → 平台适配 → 审核 → 发布 → 数据复盘 → 下一轮内容。
- 桌面端与 Web 端共享一套信息架构；手机与 Pad 共享一套响应式信息架构。
- 平台能力必须区分自动发布、辅助发布和仅导出发布包三种情况。
- 用户数量和客户数量必须标注为官方披露、自报数据或低置信度资料。
- 后续产品文档默认使用中文；产品名、平台名、技术名词和必要的英文缩写保留原文。

### 任务二：定义产品策略

- [x] 明确产品定位、用户画像、MVP/V1.5/后续版本范围、北极星指标、验证计划和风险控制。

- [x] 明确用户角色、核心对象、状态流转、功能需求、平台策略、AI 质量、安全、数据埋点和验收标准。

- [x] 明确桌面端/Web 端布局、页面清单、内容编辑器、发布日历、数据分析、权限、快捷键和响应式行为。
