# SourceFlow 产品需求文档（PRD）

版本：0.1
状态：已确认方案，供产品、设计、研发评审
日期：2026-09-19
负责人：SourceFlow 产品团队

## 1. 目标与非目标

### 1.1 产品目标

让高频多平台内容生产者以一条内容源为起点，在一个工作区内完成内容理解、AI 复用、平台适配、审核、发布、复盘和轻量线索转化。

### 1.2 MVP 目标

- 30 分钟内完成一条长内容的首次内容批次生产。
- 一条源内容至少生成 5 个可编辑资产。
- 支持至少 3 个国内平台和 3 个海外平台的内容适配；具体自动发布能力按平台授权情况分级。
- 支持个人和 1—10 人小团队协作。
- 发布后 24 小时内能看到跨平台基础数据和下一步建议。

### 1.3 非目标

- 不替代 Premiere、Final Cut、剪映等专业剪辑软件。
- 不在 MVP 做全量评论/私信客服中心。
- 不承诺所有平台均支持全自动发布。
- 不在 MVP 做完整 CRM、订单管理和营销自动化。
- 不以生成虚假名人、虚假新闻或规避平台审核为产品能力。

## 2. 用户与角色

| 角色 | 说明 | 关键权限 |
| --- | --- | --- |
| Owner | 工作区创建者/付费负责人 | 全部权限、账单、删除工作区 |
| Admin | 管理工作区和成员 | 成员、品牌、账号、模板、发布配置 |
| Editor | 生产和编辑内容 | 上传、生成、编辑、提交审核 |
| Reviewer | 审核内容 | 查看、评论、批准、退回 |
| Analyst | 查看数据和报表 | 查看数据、导出报表、创建复盘 |
| Viewer | 只读协作者/客户 | 查看被授权的批次和报表 |

## 3. 核心对象与状态

### 3.1 核心对象

- **Workspace**：工作区，包含成员、品牌、账号、内容和计费。
- **Brand**：品牌资料、语气、禁用词、CTA、视觉规范。
- **Channel**：一个平台账号连接，例如某个抖音号、YouTube 频道或小红书账号。
- **Source**：原始内容源，含文件、链接、转写和处理状态。
- **Content Batch**：围绕一个 Source 或主题产生的一组内容资产。
- **Asset**：一条可发布内容，含媒体、文案、平台、版本和指标。
- **Campaign/CTA**：内容关联的活动、链接、表单或线索入口。
- **Insight**：基于数据产生的复盘结论和下一步建议。

### 3.2 内容批次状态

`draft → generating → needs_review → approved → scheduled → published → measuring → archived`

异常状态：`generation_failed`、`publish_failed`、`blocked_by_platform`、`data_sync_failed`。

状态变更必须记录操作者、时间、原因和来源版本。

## 5. 详细需求

### 5.1 工作区与首次设置

#### FR-001 工作区创建

用户注册后必须完成以下最小设置：创作者类型、主要平台、发布频率、品牌名称和内容语言。可跳过非必填项，但系统要在首页显示未完成设置提醒。

验收标准：

- 创建工作区后进入空状态首页。
- 首次设置可在 3 分钟内完成。
- 设置内容可在“品牌资料”中再次修改。

#### FR-002 平台账号

每个 Channel 显示平台、账号名称、头像、授权状态、最近同步时间和可用能力：`publish`、`analytics`、`comments`、`profile`。

验收标准：

- 授权过期时在首页、日历和账号页均显示提醒。
- 断开账号前必须二次确认，并说明历史内容数据是否保留。
- 平台能力不足时使用“导出发布包”作为降级动作。

### 5.2 内容源与理解

#### FR-003 内容源导入

支持：MP4、MOV、MP3、WAV、PDF、DOCX、TXT、网页 URL、公开视频 URL、直接粘贴文字。大文件进入后台队列，前端实时显示阶段：上传、转码、转写、分析、完成。

#### FR-004 内容理解

系统生成：

- 带时间戳的逐字稿。
- 章节和主题分段。
- 关键观点、金句、事实性陈述。
- 可剪片段候选，含开始/结束时间和推荐原因。
- 风险提醒：敏感词、可能需要核验的数字、疑似版权素材。

验收标准：

- 每个 AI 结论可展开查看原文或时间戳来源。
- 处理失败时保留原始文件并允许重试。
- 用户可手动修改转写文本，修改后重新生成的资产以新版本保存。

### 5.3 AI 内容复用

#### FR-005 生成任务

用户选择平台、内容类型、数量、语气、目标受众和 CTA 后创建生成任务。系统显示预计额度消耗和任务队列位置。

首批模板：

- 60—90 秒短视频脚本。
- 15—30 秒短视频钩子。
- 小红书/公众号图文结构。
- 知乎回答提纲。
- 视频号/抖音发布文案。
- LinkedIn/X 帖子。
- 标题、摘要、章节、评论区置顶文案。

验收标准：

- 支持一次生成多平台、多数量资产。
- 生成结果保留 prompt 配置、源版本、模型版本和时间。
- 用户可对单个结果“保留、重写、缩短、换语气、回到源文”。

#### FR-006 平台适配

适配器在生成前和发布前各检查一次：媒体比例、时长、字数、标题、标签数量、链接限制、敏感词和 CTA。

平台能力分级：

| 等级 | 含义 | 用户动作 |
| --- | --- | --- |
| A | 支持自动发布和数据回传 | 直接排期 |
| B | 支持数据回传但需人工发布 | 复制内容或确认后发布 |
| C | 仅支持导出适配包 | 下载媒体、文案、标签和发布清单 |

### 5.4 编辑、审核与发布

#### FR-007 资产编辑

编辑器分为媒体区、文案区、平台检查区和 AI 助手区。必须支持自动保存、撤销/恢复、版本命名、平台版本切换和批量替换 CTA。

#### FR-008 审核流

内容可提交给指定 Reviewer；Reviewer 可批准、退回并填写原因、评论某段文字或某个时间点。退回后生成新版本，旧版本保持可查看但不可继续发布。

#### FR-009 排期

支持月/周/日视图、拖拽移动、批量选择、按平台筛选、按品牌筛选、时区设置、发布时间冲突提示和最佳时间建议。

#### FR-010 发布

发布前必须显示最终预览、账号、时间、媒体、文案、CTA 和风险提醒。失败时显示平台返回原因、下一次重试时间和导出按钮。

### 5.5 数据与复盘

#### FR-011 数据看板

基础指标：曝光/展示、播放、完播率、点赞、评论、分享、收藏、涨粉、点击、线索。每个指标显示平台原始值、同步时间和统计口径。

#### FR-012 复盘建议

至少输出：

- 高表现内容及其主题、开头、长度、发布时间。
- 低表现内容可能的原因，但必须用“可能”而不是事实断言。
- 可重剪片段、可换标题、可跨平台复用的资产。
- 下周 3—5 个选题建议和推荐来源。

建议必须支持“采纳并生成内容批次”。

### 5.6 线索转化

#### FR-013 CTA 与归因

用户可创建 CTA 模板，绑定链接、短链、UTM 参数或表单。每个内容资产保存 CTA ID 和来源渠道。表单收集字段默认最小化：姓名/联系方式/备注/来源内容。

MVP 不做销售漏斗和自动跟进，仅提供线索列表、标签、导出和来源统计。

### 5.7 团队与计费

#### FR-014 权限

权限按工作区、品牌、内容批次和操作类型组合。Owner/Admin 可以管理账号和计费；Editor 不可修改套餐；Viewer 不可导出含个人信息的线索。

#### FR-015 用量

用量项：源内容分钟数、生成资产数、视频渲染分钟数、连接账号数、品牌数、成员数、存储空间。所有用量在“账单与用量”中可追溯到具体任务。

## 6. 平台策略

首批建议优先级：

1. 国内：抖音、视频号、小红书、B 站、公众号。
2. 海外：YouTube Shorts、Instagram、TikTok、LinkedIn、X。

每个平台都必须有一份能力卡片，明确授权范围、支持格式、发布限制、数据字段和降级方式。没有稳定授权能力的平台，不在市场宣传中写“全自动发布”。

## 7. AI 质量与安全

- 生成内容必须保留源内容引用位置。
- 数字、时间、人物、引用和医学/法律/金融结论标记“建议核验”。
- 品牌禁用词和平台敏感词在生成前后各检查一次。
- 账号授权 token 加密存储，前端不显示完整 token。
- 支持删除源文件、转写和衍生资产；删除操作需要二次确认。
- 生成任务的 prompt、模型版本和结果版本可审计，但默认不向其他成员暴露私人草稿。

## 8. 数据埋点

### 关键事件

`workspace_created`、`channel_connected`、`source_uploaded`、`source_processed`、`batch_created`、`generation_started`、`generation_completed`、`asset_edited`、`review_submitted`、`asset_scheduled`、`publish_succeeded`、`publish_failed`、`analytics_synced`、`insight_accepted`、`lead_created`、`plan_upgraded`。

### 每个事件的公共字段

`workspace_id`、`user_id`、`role`、`brand_id`、`batch_id`、`asset_id`、`channel_id`、`platform`、`source_type`、`plan`、`client`、`occurred_at`。

## 9. 非功能需求

- 首屏加载目标：常规网络下 P75 ≤ 2.5 秒。
- 文案生成首个结果目标：P75 ≤ 30 秒；视频转码采用异步任务，不阻塞页面。
- 任务状态可恢复，浏览器刷新后不丢失队列。
- 数据导出支持 CSV/JSON；媒体导出支持 ZIP 发布包。
- 关键操作可访问性：键盘可达、对比度符合 WCAG AA、状态不能只用颜色表达。
- 个人信息、授权信息和账单信息分离存储并做权限校验。

## 10. 版本验收清单

- [ ] 新用户可以创建工作区并连接至少一个平台账号。
- [ ] 用户可以上传一条长内容并看到转写、章节和候选片段。
- [ ] 用户可以生成 5 个以上平台资产并逐条编辑。
- [ ] 用户可以提交审核、退回、批准和查看版本记录。
- [ ] 用户可以排期，平台不支持自动发布时可以导出发布包。
- [ ] 用户可以查看内容批次的基础数据和复盘建议。
- [ ] 用户可以绑定 CTA 并看到线索来源。
- [ ] 管理员可以查看用量、修改套餐和管理成员权限。
