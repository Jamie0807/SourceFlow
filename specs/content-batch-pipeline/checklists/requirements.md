# Content Batch Pipeline 需求质量检查清单

## 范围和用户价值

- [ ] 是否明确第一阶段只做 Web + API + Worker？
- [ ] 是否明确输入格式、文件大小和音视频时长限制？
- [ ] 是否明确只生成抖音、小红书、视频号导出包？
- [ ] 是否明确不做真实平台发布和视频成片渲染？
- [ ] 是否能用一句话解释用户为什么需要这个功能？

## 需求完整性

- [ ] 注册、登录、刷新、登出有验收标准。
- [ ] Workspace、成员和三种角色有权限边界。
- [ ] Source、Batch、Asset、Review、ExportJob 和 TaskRun 有状态定义。
- [ ] 上传、处理、生成、编辑、审核、导出都有成功、失败、重试和取消路径。
- [ ] 火山引擎 Provider 和 Mock Provider 的边界明确。
- [ ] 资产生成结果可追溯到源内容、版本和生成配置。
- [ ] 导出 ZIP 结构、目录和文件内容明确。

## 非功能和安全

- [ ] 所有资源按 workspace_id 校验归属。
- [ ] Access Token、Refresh Token、Cookie 和密码处理规则明确。
- [ ] 不把火山引擎密钥、数据库密码和 Redis 密码写入仓库。
- [ ] 长任务具备幂等、重试、取消和状态恢复。
- [ ] API 有统一错误结构、request_id 和健康检查。
- [ ] 日志、trace、截图和测试数据不泄露敏感信息。
- [ ] 数据库迁移、备份和回滚策略明确。

## 测试可验收性

- [ ] 每个 P0 用户故事至少对应一个 Vitest 或 Playwright 测试。
- [ ] React 交互有 React Testing Library 测试。
- [ ] 火山引擎真实调用不会进入默认 CI。
- [ ] Playwright smoke 在无真实 AI 凭证时可以用 Mock Provider 通过。
- [ ] 有 360px、1280px、1440px 的响应式检查。
- [ ] 覆盖失败、空、加载、重试和权限状态。

## 交付和追踪

- [ ] 每个需求都有对应 plan 和 tasks。
- [ ] 每个任务列出了依赖、Worktree、文件和完成标准。
- [ ] PR 和 push 的 CI 门禁已列出。
- [ ] 构建产物、Docker 镜像、迁移和发布清单有记录位置。
- [ ] 没有未解决的范围歧义、占位标记或隐含的外部凭证依赖。
